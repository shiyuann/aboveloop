# 可行性试验与测试纪律

> 写测试，或引入一个没亲眼验过的新能力时读。词表在 [SKILL.md](../SKILL.md)。

| 词 | 意思 |
| --- | --- |
| 可行性试验 | 回答「这条路通不通」的一次性试验。它的脚本用完就丢。 |
| 测试 | 回答「代码写得对不对」的自动检查。它留在仓库里，每次都跑。 |
| 静默失败 | 出了错，却不报错，比如拿到 200、解析出 0 条。 |

# 可行性试验

**新能力先出试验结论，再进架构。** 结论出来之前，不动产品代码。

## 什么时候必须做

满足一条就要做：

- **引入没亲眼看过的外部能力**：新的生成模型、新 API、新的渲染栈、没探过的数据源。文档说能，不算能。
- **新依赖碰到打包链**：原生模块、wasm、字体、二进制。开发环境里绿了不算。真机或发布的产物里跑过才算。
- **好坏是主观的**：生成质量、视觉还原这类契约断言不了的东西。先把「什么叫好」量化成阈值，再动手。

## 怎么做

1. **先写通过标准。** 写量化的阈值和样本矩阵。一张图好不算好：一个样本不能定性。
2. **用真实的输入。** 真实的数据、素材、目标硬件。合成的 fixture 验得了契约，验不了效果。
3. **在生产存储上试时，用构造保证隔离。** 每个写出去的键都经过同一个前缀。前缀在客户端里拼，不在每个调用处拼。试验前后各读一个真实的对象比一比，确认没碰到它。
4. **结论写回 spec 或 plan 的「待查清」**，带数字：通过率、耗时、字节数、单价。
5. **每个试验写清没过怎么办**：换路径、砍范围，或重做。试验不拖住后面的事。

## 生成效果怎么评

| 维度 | 怎么量 | 注意 |
| --- | --- | --- |
| 保真（主体没被偷改） | 主体区域的 SSIM 或色差阈值。logo 和文字用 OCR 逐字比对 | 不接受「差不多」 |
| 合规（平台规格） | 像素断言：底色、主体占比、画幅 | 能断言，就不用眼看 |
| 构图、美观 | 人评。先定评分表（哪几项、各几分），样本够了再下结论 | 人评也要能复现 |
| 成本 | 单次的耗时和单价 | 这是决定自己托管还是租用的数字 |

- **类目对，不等于实例对。** 模型常保住「粉色针织毛衣」这个类目，却换掉针法、色号、纹理这个实例。缩略图上看全过，懂行的人一眼看出货不对板。保真检查必须同尺度并排，加特征级的量化。
- 没过的样本留下来。它们是这个能力以后的回归集。

# 测试纪律

**功能没被实测跑过，就当它不存在。** 这类产品的失败不是崩溃，是静默失败：改错了不抛异常，数据悄悄不对，没有人发现。所以测试只有一个目标：让静默失败变成响亮的失败。

## 两层，不重叠

每个项目的测试分两层：

- **自动化**：用合成的 fixture，快，每次都跑。
- **对着真实世界**：只做自动化做不了的事。改到相关部分时才跑。

自动化从不打真实的数据源。每层跑什么、在哪跑，写在各项目的 `AGENTS.md` 里。

## 只测四种东西

要测的东西同时满足两条：会静默失败；错了代价大。其中两种所有项目都有：

- **跨层契约**：A 的产出、中间的契约、最终的形状。三处各自都对、合起来不对，是最贵的 bug。
- **静默返回空**：拿到 200 却解析出 0 条，是故障，不是成功。

另外两种，各项目填自己最贵的失败，比如内容哈希稳不稳、质量闸放行的方向、权限边界、撤不回的操作。不硬凑四条通用的。

**不测这些**（写了只是负担）：

- UI 文案、样式、快照对比。
- mock 掉 IO，再断言「函数返回了对象」。
- 纯格式转换的逐函数单测。
- mock 数据库。库是一个文件（比如 SQLite），就建一个小的 fixture 库，毫秒级。能打真库，就打真库。

**加用例的规则：** 修一个 bug，加一条用例。只加在最外的那一层。先看着它失败一次。用例数增长要有理由。清单长到几十条，说明有人拿数量当安全感。

## 容易以为测过了的地方

- **一个样本不能给一整列定性。** 抽样会让人误判「没问题」，也会误判「有问题」。要定性，就全量数。
- **边界「通过」了，先确认测的是它真正的出口。** 权限函数对、页面的数据层对、最终的 HTML 里却全都在：三件事可以同时成立。测最后给用户的那个东西。
- **打包改变的不只是产物的位置。** 原生模块的 ABI、用户数据的路径、能不能设环境变量，都会变。比如依赖 `NODE_OPTIONS` 的方案，在 `npm run` 下能用，在双击打开的应用里一定失败。
- **后台等待不用墙钟判超时。** 笔记本会睡眠。醒来时 deadline 早过了，会把早就完成的外部任务判成超时。按有效的轮询次数计。醒来先再问一次。

**CAUTION:** 发布前先跑测试。测试红了，不发布。

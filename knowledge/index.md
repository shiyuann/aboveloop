# Knowledge base index

This folder holds the design of aboveloop. All pages are in ASD-STE100 Simplified Technical English (the rules are in `entry`). The terms are in [L2-loops §0](spec/L2-loops.md#0-terms). The rules for levels, the graph and conflicts are in `knowledge` (knowledge-base).

- **`spec/`**: how it must work (the target), in three levels. The level is the start of the file name. A part that is not built yet has a ⬜ mark.
  - **L1**: why aboveloop exists, for whom, and the principles. Only the owner changes it. Every session reads it.
  - **L2**: the key decisions, each with its reasons (Why).
  - **L3**: the details of how it must work. In aboveloop, L3 describes only code and data contracts; the steps of a procedure are in its skill ([L2-plugin §2](spec/L2-plugin.md#2-entry-the-start-for-all-rules-and-skills)).
- **`plan/`**: open work. `plan/index.md` is the graph of all open work: one chart, the `Now:` line and the next step of each issue; a session agent keeps it, and the release removes its ✅ items (L2-loop-dev §4). Each other numbered plan is the plan of one issue: on its branch `issues/<N>` in both modes, and on `main` after the merge, with its done nodes ✅. It is not in this table. The first release after all its nodes are ✅ removes it (L2-release §2.8). A project can also keep the plan of a milestone: no number, one row in this table, and the release does not remove it (L2-loop-builder §1). In the semi-automatic mode, code starts after the spec step of the issue: its last spec review, or the short plan of a light spec. Not a level.
- **`reference/`**: evidence: doc quotes, measurements, verbatim words. Append-only, except the deep-verify reports: a report leaves with the plan of its issue ([L2-release §2.8](spec/L2-release.md#28-a-release-removes-finished-plans-and-deep-verify-reports-)). Not a level.

## Pages and what they build on

This table is the only dependency graph. "Builds on" names the pages that a page comes from, and the L1 items that it cites. A page builds only on pages of its own level or a higher level, with no loops. "Checked" is a date that a release writes. A change of a page examines the body of each page whose "Builds on" names it. Change a body that no longer holds. Do not change a header or a Checked date. A review reads the git diff of the body. A change of words only (a typo, a link) does not count.
